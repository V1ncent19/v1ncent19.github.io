# 3D 游记 Playground 工程指导 · 大理石日晷

状态：设计与施工计划。当前 `/playground/` 中的双层庭院仍是可运行的对照版本。这份文档定义新的「大理石日晷浮空沙盘」，实施和验收均在 Playground 分支进行。视觉质量优先，可以为近看仍可信的建模、贴图和光影增加资源开销。首版以桌面端完整体验为目标。

## 1. 美术方向与资产规格

场景是一件浮空的微缩建筑模型。开场能辨认出圆形岛体、浅水边界、四扇花窗和中央树，靠近时再看到石材、黄铜、焊缝和玻璃起伏。整体用暖白、石灰、墨灰和少量黄铜建立层次，饱和色集中在花窗及其投影和倒影。保留《The Artisan of Glimmith》参考里手作微缩模型的感觉，造型与材质以本站资产为准。

| 资产 | 造型与建模 | 材质与细节 |
|---|---|---|
| 浮空底盘 | 主盘、分层侧缘、黄铜收边和底部结构分别建模。明显的倒角与接缝做出几何厚度，俯视与低角度都能读出轮廓。 | 温润的象牙白大理石，低对比微纹与轻微粗糙度变化。黄铜有清晰但克制的反光，转角允许极轻的磨损，避免满场做旧。 |
| 日晷与足迹 | 同心圆、刻度和几段足迹线沿干燥石面嵌入。主要刻度用实物嵌条，细小纹样用遮罩或贴图。 | 黄铜与石面齐平。和玻璃投影叠放时保持刻度可读，不抢彩光。无需画成每篇游记的真实地理轨迹。 |
| 花窗与基座 | 保留四扇现有花窗的图案、拱形和长宽比。制作统一的承座接口，窗框倒角、金属边条与主要接缝用几何表达；内部分片优先沿用原有图集。 | 拱内玻璃、有厚度的窗框和接缝分别渲染。引线的位置跟随原图的分片边缘；玻璃与框之间不露白，不出现偏移或重叠的黑线。 |
| 中央树 | 低矮树干、几条有姿态的分枝和疏朗的云朵状冠层。树冠留空让视线穿过，避免在初始镜头中盖住后排花窗的主体。 | 枝干用哑光墨灰，冠层与飘落物默认浅暖灰或白玉色，透光处可有很轻的季节色。 |
| 外围浅水 | 环形浅槽置于石面下方。水下边缘有深浅层次，槽外与可读的底盘轮廓相接。 | 水面总体平静，靠微波法线轻轻扰动天空与花窗倒影。水底保持暖灰中性，避免水色与花窗竞争。 |

建模建议用 Blender 保留可编辑母版。统一尺度、命名和枢轴，导出 GLB 后以 `+Y` 向上复核。高精度优先用于轮廓、倒角、大理石边缘、嵌条和玻璃近景。微纹理、金属细划痕、石材小凹坑用法线或粗糙度表现。颜色贴图按 sRGB 使用，法线、遮罩、粗糙度与金属度按数据贴图处理。重点近景可以上 2K–4K，投影遮罩保留足够分辨率；远景资源按镜头验收之后再分级。保留贴图和环境光图的来源与授权记录。

## 2. 空间与扩展规则

保留现有世界坐标约定：`+X` 是东，`-Z` 是北，`+Y` 向上。开场建议使用俯看全盘的三分之四视角，镜头朝向北偏东 30° 作为构图起点。默认太阳沿用北偏西 45°、仰角约 32°作为第一张对照图的光位；实际朝向从相机 `position → target` 的水平投影验收。镜头和太阳参数分开配置。最终可以为四窗开场微调相机高度、目标点和视场。

第一圈放现有四扇实窗，角距 90°。中心保留树与树池区域，树池外有一条连续的干石环带，花窗设在环带外侧。默认让窗面朝环带开放，玻璃两面可看，窗框和座台用厚度区分正背面。花窗不做成遮住整圈的墙，近侧窗不能遮掉后排辨识所需的图案。用相机可见性和投影落地范围反推树冠高度、窗高、环带宽度与首圈半径，先做白模再锁定尺寸。

- 位置由 `ringId`、`slotIndex` 与各环的起始角计算。半径为 `r`，方位为 `θ` 时，平面坐标为 `x = r sin θ`、`z = -r cos θ`。环上两个相邻槽位的中心弦距是 `2r sin(π/n)`；它至少要覆盖窗底座最大平面宽度、净距和选中留白。公式只用于给候选槽位定尺寸，最终还要检查实际包围盒、窗口重叠、树冠遮挡与相机停靠点。
- 建议首圈按八个位做容量白模，首版按隔位放四扇，四个余位默认不显示窗框。后续先填已有空位，满了再加外环，并同步扩展石盘、水边界和阴影接收面。已有花窗不因追加游记而旋转或重排；每一圈新增的停靠点需重新检查。规模增大时按环组织镜头和加载范围，全景保持可辨识，重点花窗进入近景再看细节。
- 槽位、玻璃资产和游记是三种独立标识。布局配置描述环、槽位与占位；`assetId` 选取玻璃与灯光图集；`travelogueId` 决定摘要、排序和链接。未占用位可以保留刻度，不参与轨道、键盘顺序和交互。四窗、八窗填满和十二窗跨环分别留验收样例；重复现有窗只用于内部构图验证。

## 3. 内容、资产与现有代码的衔接

继续使用 `app/playground/page.tsx` 的独立入口和现有 `noindex` 约定。`components/playground/PlaygroundExperience.tsx` 已把 3D 画布与普通链接分开，保留这条边界。现在的 `StainedGlassScene.tsx`、`GardenPanCamera.tsx`、`gallery-layout.ts` 和 `glass-optics.ts` 是对照版本；复用玻璃、接收面求交与共享时钟等可复用部分，日晷布局和双模式镜头在新场景中实现。原型细节见 [现有花窗 Playground](FEATURE_PLAYGROUND_STAINED_GLASS.md)。

| 位置 | 拟放内容 |
|---|---|
| `content/playground/travelogues.json` | 手工维护的游记出场顺序、玻璃关联与可选双语摘要。标题及地址优先引用已有游记元数据，保留 Anitabi 的 `just-because` 路径。 |
| `assets-src/playground/` | 现有窗图、配准参数和可编辑美术源；新场景的 Blender、模型高模和分层贴图放到 `sundial/` 子目录。 |
| `generated/playground/` | 由资产脚本生成、供代码导入的验证清单、图集层映射与尺寸元数据。 |
| `public/assets/playground/sundial/` | 浏览器直接请求的 GLB、纹理、环境光图、预览与音频。只保留运行时需要的发布副本。 |
| `components/playground/` | 布局计算、石盘及水面、光照、粒子、镜头状态、门户及无障碍界面。`out/` 继续作为网站导出结果。 |

清单的最小形态示意，字段名可随现有游记索引接口调整：

```json
{
  "version": 1,
  "travelogues": [
    {
      "id": "france-2024",
      "tripId": "france-2024",
      "assetId": "france",
      "slotId": "ring-1-01",
      "summary": { "zh": "在巴黎的街巷与美术馆之间。", "en": "Between the streets and museums of Paris." }
    }
  ]
}
```

摘要文案是格式示意。顺序由清单数组给出，空间位置由槽位确定；两者可以各自调整。首版复用 France、PTES、Guatemala、Anitabi 的四份窗图，`scripts/build-playground-glass.mjs` 继续读取已配准的 `assets-src/playground/window-gallery.mjs`，按 `assetId` 输出图集层。首轮须核对每扇窗的比例、裁边、UV 方向和线条，再迁移场景。新增游记时只需准备窗图和配准记录、添加清单条目、分配空槽并运行生成校验。构建时检查游记与双语链接可解析、ID 唯一、槽位未占用、资产完整。站点继续可静态导出。

## 4. 实时光影

### 太阳、玻璃与地面共用状态

时间滑块推进一条可调的日照弧，同时更新方位角和仰角。它代表沙盘的展示时间，持续拖动时连续出光，不依赖具体地点日期的天文数据。用一个世界坐标单位向量表示从场景指向太阳的方向，平行光沿反方向照射；阴影、地面反查采样和水面高光都从这个向量取值。玻璃每片的相位、透光颜色和亮度用同一份图集与时钟，窗面和投影在同一帧取样。保持上轮认可的玻璃轮番亮暗，避免高频全窗闪烁。

1. **窗面折射与反光。** 用 `MeshPhysicalMaterial` 的 `transmission`、`ior`、`thickness`、`roughness` 和环境光产生通透感，开启透射时保持 `opacity: 1`。折射率可先在约 1.45–1.52 内调试，厚度按建模尺度设置。每片采用不同的微法线和粗糙度，让视角变化时反光有细小差异。保留共用的玻璃图集，优先验证多窗重叠或从背面观看时的透射。单纯使用三维材质的透射不会在地板上得到彩色焦散，地面光需要独立计算。
2. **石面彩光。** 扩展 `glass-optics.ts` 已有的反投影。对石面采样点沿世界坐标的向阳方向反查最近的候选窗平面，换算成玻璃 UV 取分片颜色、透光率、铅条遮罩和动态相位。先做每扇窗的接收面范围裁切，再逐像素采样。用太阳有限角度对应的采样范围软化分片与外缘，近端看得出单片中心和大致形状，远端允许更柔和。主要窗框、树和岛体可以挡光；玻璃区域不能同时被普通阴影当成不透明墙压黑。斜入射或光斑离开岛体时应自然减弱、滑出边界。多扇彩光有明显重叠后，再根据对照图决定是否加入多窗透射叠合。彩光调制石面受光，保留砖纹或大理石微纹、嵌线和粗糙度；色块边角可以模糊，中心不要被整片混成灰白。
3. **悬停回馈。** 单窗使用缓入缓出的局部暖色背光，给窗面一层提亮，给对应接收面加一层轻微扩开的光晕。背光与全局太阳是独立的光源。保留太阳投影原来的方向、边缘和位置；当太阳打不到地面时，局部反馈也可成立，但保持弱于日照投影。键盘聚焦触发相同状态。按需预加载环境音，首个明确互动后才允许播放，提供静音控制；快速扫过多扇窗时不逐个叠播。

### 浅水、落花与景深

- **浅水倒影。** 用镜像相机渲染独立的水面反射缓冲，裁掉水面以下不该进入反射的几何，并排除反射通道本身。水面合成加菲涅耳角度权重、浅滩深度衰减和低幅双法线扰动，保留清楚但弱于原物的玻璃倒影。若二次渲染中高透射玻璃无法稳定出现在倒影里，用同一张图集、同一相位生成仅供反射通道使用的简化窗面。整体倒影应随镜头和时间改变，水体不需要湍流或大幅镜面扭曲。
- **树冠与飘落物。** 用 `THREE.InstancedMesh` 配合顶点着色器渲染约 200–300 片。实例预设种子、出生相位、大小、姿态与降速；逐帧更新一个时间 uniform，GPU 计算摆动、缓慢螺旋和 `mod` 循环。靠近树冠及触底处渐显渐隐，接地或出界之后才复位。保留正确的深度遮挡并限制透明叠层，不做逐片 CPU 更新。减少动态模式下静止或隐藏飘落物。
- **空气与微缩焦距。** 用低密度 `THREE.FogExp2` 拉开模型与背景，远处仍应可见窗框轮廓。主视图使用统一的后处理入口；轨道模式可将焦点平滑移到选中窗，俯瞰开场让四扇都清楚，自由探索允许较深的景深或关闭。重要内容和链接作为画布外 DOM 渲染，不参与模糊。谨慎提亮高光，必须保留玻璃饱和色与白石纹理。

## 5. 浏览、选择和传送门

| 状态 | 行为 | 退出与保护 |
|---|---|---|
| `rail` · 轨道 | 开场先给全景。滚轮或上/下一个按钮沿展品顺序移动；停在能看正面并留出投影的预设机位。用增量阈值、阻尼与选中滞后来抑制触控板抖动。每个停靠点显示对应摘要。 | 只有画布内的轨道浏览区域接管普通滚轮，保留页面滚动与浏览器缩放。提供键盘上一扇／下一扇和普通链接。 |
| `free` · 自由探索 | 进入时沿用当前视角，再允许拖拽旋转和缩放。限制最低视角、缩放和目标点范围，避免进入石盘或墙体；选中链接和时间滑块继续可用。 | 区分点击与拖拽，拖动结束不触发进入。切回轨道时从当前姿态移向最近或已选停靠点，避免瞬间跳转。 |
| `portal` · 进入游记 | 用户点击可用花窗或专用进入控件后，以它的玻璃中心为目标短推镜。过窗瞬间用屏幕空间折射和颜色淡入盖住交接，再进入对应游记。 | 唯一一个转场控制器负责锁定导航和释放状态，过窗前允许取消。路由超时、浏览器返回或恢复时移除遮罩并解锁。减少动态时直接走链接。 |

用稳定的 `activeTravelogueId` 和时间值跨模式保留选中窗与太阳状态。轨道标记与拖动相机分别使用独立输入，拖动时间滑块不会带动场景旋转。点击前可以预取对应页面。现有 `lib/travel/log/entry-transition.ts` 提供 `beginTravelEntry()` / `clearTravelEntry()`；实施时验证门户最后一帧与游记原有蓝幕的交接，只保留一次可辨识的揭开动作，不能中间露出白帧或播放两次转场。返回 Playground 时恢复所选花窗和原浏览模式。3D 初始化失败、失去上下文或用户禁用动画时仍可通过普通列表读摘要、打开文章；首版以桌面交互验收，触屏至少能使用按钮与链接。

## 6. 施工顺序与验收门槛

| 阶段 | 交付物 | 进入下一阶段前验收 |
|---|---|---|
| A · 比例白模 | 石盘、树冠剪影、浅槽、四个实窗代理；八位与十二位调试样例；全景与停靠机位。 | 同一张俯视图核对环宽、径向净距与槽位顺序；默认镜头里四扇都可辨认；八位满载和十二位跨环不重叠，新增槽不改变原窗位置。 |
| B · 材质与建模 | 底盘、嵌线、窗框、中央树和浅水的高精资产；四套已确认窗图。 | 用全景、紧贴花窗和低角度三组固定镜头检查倒角、窗线与拱边对齐、材质层次、接缝和占色比例。通过后再锁定材质基准和曝光。 |
| C · 光影与动态 | 日照滑块、太阳阴影、实时彩光、薄水反射、落花与景深。 | 在同一镜头截取低、中、高三个太阳位置；检查阴影和彩光方向一致、相邻玻璃中心可辨、远端自然过渡、石纹未丢。录短片检查窗面和地面同相闪动、水面不抖、近景反光随视角变化。 |
| D · 交互与路由 | 滚动轨道、自由探索、摘要、键盘访问、声音控制和门户。 | 用鼠标、触控板和键盘核对模式切换、滑块、悬停、拖动不误点；测试四篇目的地、Back、取消、超时、减少动态与画布失败。静态导出中验证资源路径及直接访问。 |
| E · 完整走查 | 相同镜头的白模与成片对照图、动作录屏、资源测量和调参记录。 | 记录冷启动、场景初次可见、纹理显存、GPU 帧时与卡顿点；分别覆盖全景、近窗、滑动太阳、门户与八窗样例。优先解决跳帧、重复下载或材质编译停顿，视觉调整用同视角对比验收。 |

高画质档是第一验收对象。首屏先展示主体和已有四扇窗，近摄用的精细模型、大纹理、背景音按需加载或预热。若反射、景深或贴图上传首先拖慢操作，先量化开销，再在次级档降低反射分辨率或刷新频率、缩小远景纹理、简化景深或减少飘落物；别让降档把窗面与地面的动态拆开。按设备和场景规模记录实测表现，不以当前庭院的资源体积为上限。

## 7. 开工前优先确认的视觉偏好

1. **树冠的颜色与季节。** 建议先用温白云冠和浅米色落花，保持花窗独占饱和色。若偏好樱花或秋叶，可以在冠层边缘加入极低饱和的淡粉或浅赭。
2. **未来槽位的可见性。** 建议首版只看到四扇，另外四位只留可用空间。若希望读者感觉这个展览会继续增长，可以在未来槽位留很浅的黄铜刻度或基座印记。
3. **太阳滑块的形态。** 建议从偏低的晨光滑到傍晚，默认停在最能读出窗面和地面投影的位置。若更看重把光线绕岛调到任意方位，可以用圆形太阳方位控件，并保留一个独立的仰角预设。

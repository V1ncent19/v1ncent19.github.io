## 一、整理原件和页序

1. 建立文件清单：稳定 sourceId、原文件名、SHA-256、像素尺寸、纸页号、内容类别、方向、疑似日期、重拍/重复关系。
2. 解码 HEIC，生成可读 JPEG/PNG；旋转、裁边、轻度透视及亮度校正只作用于派生图，保留原图和转换关系。反光不能靠增强恢复时，在清单标记。
3. 文字按纸页/段落编号；地图按整图、日期标注、箭头、时间、地名编号。图块裁切须保留与原图的坐标对应。
4. 初步重建页序，区别纸页号与照片号；同一地图的增量版本并列比较，不累计成重复行程。

验收：35 张都有清单记录，原件未改动；任何文字/地图标注都能返回原图；重复和页序疑问显式列出。

## 二、小样识别，先定核对格式

首批选三类代表：IMG_3035（带时间行程表）、IMG_3051（长段正文及外文专名）、IMG_3069（路线图）。这是样例，不是已认可的转录。

识别以逐页视觉读取为主，密集区域切块放大再读；普通 OCR 如使用，只作候选，不能把输出直接当定稿。中英法文保留原语种、重音、缩写、口语和原有段落。

每段保存三层，不能互相覆盖：

1. **忠实转录**：原字、原拼写、原时间；涂改可辨时保留修订关系。无法确认用 `[疑读：A / B]`、`[无法辨认]`，不自动补全文句。
2. **校订建议**：标准地名、拼写建议、疑似错字、断句；单列理由，不覆盖原文。
3. **结构提取**：日期/时间、地点、活动、交通、计划/实际/未遂/提及、来源与待确认项。只出现某景点名称不能直接算去过。

### 第一轮交付格式

主核对入口采用**本地 HTML 对照册**：左侧可放大的校正图，右侧转录；用稳定段落 ID 对应图块。另设提取结果、疑问清单和地图标注页。支持按页、日期及待确认状态定位；默认私有，不加入站点路由。

同时交付 UTF-8 Markdown 转录稿和 CSV 疑问/行程表，避免只能在专用查看器里修改。首轮无需用户直接编辑 JSON。用户可在 Markdown 改字或按问题 ID 回复；若查看器提供编辑，必须有明确导出/重新载入功能，不能仅依赖浏览器缓存保存校订。

## 三、全量转录和第一轮人工核对

- 按日期/纸页分批，先独立识别，再结合相邻页复核；避免先猜行程，再把字读成预期地名。
- 地图保留打印底图文字与用户手写标记的区别；逐条记录箭头方向、时间、地点和版本关系。
- 对照行程表、实际感想和手绘图找冲突；例如计划到访但正文说未入场，应保留两个记录并建立关联。
- 第一轮请用户重点确认日期、行程性质、外文专名、疑读和地图版本；其余明确段落可批量确认。未解决项保持 unknown，不以语言润色掩盖。
- 每次校订保存变更及来源链接。转录原文、用户校订、面向读者的整理稿分别保存。

验收：所有源文件有处理状态，所有段落有 sourceId；未解问题有列表；已确认与推断可区分。高影响疑问未解时不把候选纳入确定路线。

## 四、重建地点、时间和路线，进行第二轮核对

先生成“每天的地点序列”，再决定连线；不先画一条漂亮路线再倒填内容。

- 地点：保存原名、标准名、城市、经纬度、坐标精度、证据和核对状态。餐厅/旅馆必须考虑同名及 2024 年地址；之后联网查官方地点资料并记录链接，查不到不强配。
- 时间：分开保存纸上原始写法与标准化日期；缺时间用空值、上午/下午或顺序。时区用地区 IANA 名称，日期未明确前不硬编码 UTC 偏移。跨午夜和跨城市另验。
- 到访：分开保存计划、实际到访、未入内/放弃、仅提及及未知；“到过门口”不等于进入参观。
- 路段：区分手绘图可支持的路线、只知两端的示意连线和基于路网计算的候选。地名坐标准确不代表两点之间路径准确。
- 手绘图可通过地标控制点辅助对齐和人工描线；拍照透视、底图变形和反光使它不能直接当 GPS。只在证据足够时跟随具体街道。
- 每段保存 from/to、交通方式（可未知）、geometry（可空）、来源、路线依据、核对状态；推断尽量附可解释理由，而非不可靠的精确置信百分数。
- 不计算或展示“真实累计里程、速度、海拔爬升”等无依据统计；若以后提供估算距离，必须明确依据与估算标签。

第二轮交付：每日行程表 + 简单可交互核对地图 + 冲突清单。用户确认“去过哪里、什么顺序、哪些连线只是示意”；无需逐点校对虚构轨迹。

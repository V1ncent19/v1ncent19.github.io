**Gallery layout refinements (2026-09-04, user requested):** the masonry no longer uses CSS multi-columns (which fill one column then the next, scattering times across rows). `gallery-view.tsx` now renders **explicit JS flex columns** and hands photos to them **round-robin** (`item i → column i % n`), so a horizontal band holds temporally-adjacent frames (top band = newest 4 left→right) while varying aspect ratios still produce the staggered masonry drift. A segmented **3 / 4 / 5 column chooser** (default 3) sits at the far right of the sort strip (`lib/i18n.ts` `gallery.columns` = "Columns"/"列数", `LayoutGrid` icon); the container width is measured via rAF + resize listener and the effective count clamps to whatever keeps each tile ≥ `MIN_TILE` 148 px — buttons that cannot fit the current width are disabled, and SSR/first-client-render both render `prefCols` so hydration DOM is identical. Tile hover now mirrors the mock's frosted-glass → white-card treatment: explicit capsule height `h-8 → h-12` (so the grow animates), rounded-lg→xl, glass→`white/95`, two absolutely-centred faces crossfade (rest: dot + "place · YYYY.MM"; hover: serif heading + full date + arrow) — image scales 105% (700 ms), bottom gradient deepens, whole tile lifts; theme-independent neutral colours so dark mode is unaffected. The overlay keeps its `gb-overlay-in` fade; the panel itself no longer uses the old `gb-panel-in` CSS rise — it now opens with a shared-element FLIP (see Request C below).

**Bilingual content model + caption presentations (2026-09-04, user specified):** the manifest now carries **9 user-filled fields** — the four text concepts `place` (country, city), `placeLocal` (specific spot), `title` (opened-card heading), `alt` (opened-card body), each suffixed `*_en` **and** `*_zh` (8), plus a shared `country_code` (ISO alpha-2). The EN page reads the `*_en` set, ZH the `*_zh` set; each falls back to the other language while empty. The old single-language `place`/`placeLocal`/`title`/`alt` keys were migrated to `*_en` and blanked (nothing hand-written was lost). Three presentations use them — **rest bar** = lang `place` · YYYY.MM (unchanged); **hover card** = theme-coloured big `place`, wrapped grey-black small `placeLocal` under it, divider, then black year-month LEFT-aligned + grey signed-degree coords RIGHT-aligned (two stacked 0fr↔1fr sub-grids auto-grow 34 → 98 px); **opened/lightbox card** mirrors `gallery_v1ncent19_desktop_lightbox_modal_state` — title block LEFT (small **theme-coloured** bold MapPin + `place·placeLocal` kicker over a big black serif `title`), travel-stamp **badge RIGHT** of that block, and the **alt description card** (bordered `bg-surface-tint` box) directly under that title block, and a primary **download button following the card** (each only while the `alt` / `originalUrl` field is set — Request D re-added the alt card and moved download out of the rail bottom). The `年月`/`country_code`/coords info moved out of the panel into a **frosted glass chip at the image-area bottom-left**; the n/total counter moved to the image bottom-right. Alt text also still feeds the image `alt` attribute. The only control is a **44 px Close pinned `fixed` to the overlay** — the prev/next buttons were removed in Request C, so switching is keyboard-only. The frosted time-location capsule (bottom-left over the image) and the n/total counter (bottom-right) both use the **sans `--font-ui` face** (`ui-text`), not the site's serif body face. The accent kicker renders only once a real `title` is authored (otherwise it would duplicate the h2's place fallback). `placeLocal` is no longer the big hover title (that role moved to `place`). Equal-height cards were **revoked** — see the adaptive layout below.

**Adaptive two-pane lightbox (2026-09-04, Request B):** at an overlay content width ≥ 768 px the opened card is a row — **left image column + fixed-width caption rail** (320 px below a 1040 px box, 380 px above). The overlay content box is measured (rAF + resize listener, initialised synchronously on tile open) and the image column is sized to **hug the photo's own manifest aspect** (`fitImage` from the generated `width`/`height`), so a **portrait stands tall with no black side margins** and a landscape fills the leftover width — nothing is `object-contain`-letterboxed. The card takes the natural height of whichever pane is taller (the rail scrolls internally, capped at the overlay height). Below 768 px it falls back to the stacked image-over-caption card with the original fixed-height figure. **Headless-verified** at 1500×1000: 0.750-ratio portrait → image column 714×952 exactly hugging the image (aspect preserved, rail right); 1.4 landscape → 1072×766 hugging it; capsule `font-family` resolves to `ui-sans-serif, …` while the h2 stays Palatino; counter `1 / 48`.

**Lightbox interaction (2026-09-04, Request C, user specified):** the two floating **prev/next arrows are gone** — only the **Close button** remains, and it is **pinned `fixed` to the overlay's top-right** rather than anchored to the image stage, so it never drifts between photos of different aspect (verified: identical x/y at 44×44 across a portrait → landscape switch). Switching is **←/→ keys only**. **Closing** happens — the Close button, **clicking any blank/backdrop area**, or **Esc** (widened to any non-button click in Request D below) — each running a shared-element **collapse back onto the thumbnail the panel opened from** (scale + fade, then unmount). **Opening** mirrors it: the panel FLIPs **out from the clicked tile's rect** (measured in a layout effect so the first painted frame is already scaled down, transform-origin at the tile's centre, double-rAF → identity). The photo swaps on ←/→ are pre-warmed (neighbours' `large` decoded in the background) and cross-fade via a keyed `<img>` + `.gb-img-in`. Reduced-motion is handled by the existing global `*` rule. **Headless-verified** with 17 assertions: no prev/next buttons anywhere, Close fixed + 44 px + drift-free, ArrowRight×2 reaches a 1.4 landscape that hugs the stage, ArrowLeft×2 returns to the start photo, and Esc / blank-click / Close each close the lightbox.

**Lightbox close + caption rework (2026-09-04, Request D, user specified):** closing is now **click-any-NON-button** — the overlay's root handler closes on any click whose target is not an interactive control (`closest("button, a, [role='button'], input, select, textarea, label, summary")` is exempt), so the **backdrop corner, the photo itself, and caption text all dismiss** the lightbox (the Close button and download link keep their own handlers; Esc and Close still close too). And because the caption rail has room again, the **alt description card is back**: the authored `alt_en` on the EN route / `alt_zh` on ZH (cross-falling back to the other language) renders as a bordered **`bg-surface-tint` info card directly under the title block** (mirroring the Stitch sample's description box but WITHOUT its fictional curator label), and the **download button now follows that card** — no longer pinned to the rail bottom. Header, alt card, and download live in ONE top-aligned column wrapper (`flex flex-col gap-5`), so they stay consecutive and nothing is bottom-anchored; an empty `alt` hides the card (never a blank box), and the download still only renders while `originalUrl` is set. **Headless-verified** with 21 assertions (the 17 Request C checks plus: alt card shown under the title carrying the EN copy; a landscape whose `alt` is empty shows no card; **click on the image** closes; **click on the caption h2** closes; blank-corner click still closes). No item has an `originalUrl` yet, so the download button itself is not DOM-asserted. **Scrollbar-gutter fix (same date, user-reported jitter):** closing the card made the far-right scrollbar "vanish then return", shifting the page left/right — the scroll-lock's `overflow:hidden` hides the classic scrollbar, widening the layout so every centred column recentres. The lock effect now also reserves that width as body `padding-right` (`innerWidth − documentElement.clientWidth`, restored on unlock), and is keyed on the open *boolean* (`openIdx !== null`) instead of `openIdx` so ←/→ photo changes never re-run it. Headless-verified with classic scrollbars forced (gap 15 px): the centred gallery column's x is pixel-identical open vs closed.

## 2. Confirmed v1 design baseline (user-locked 2026-09-04)

The current visual framework is the **locked v1 baseline**. Later phases add content and features on top of it. Do **not** restyle layout, palette, header, or typography without asking the user first. Concretely:

- **Palette tokens** — authoritative single source: `app/globals.css`. Light paper `#f5fafd`, sky-cyan brand `#1ba7c9` (deliberately deeper than dark so it reads on near-white), ink `#171c1f`; dark slate `#0c1219`, crisp cyan `#3ccfff`. Home's palette wins every per-page conflict (Stitch home-mock palette = truth). Utility names are `bg-surface`, `text-muted`, `border-line`, `text-brand`, etc., mapped `@theme inline` to the CSS vars.
- **Identity** — every page header: `Tuorui "v1ncent19" Peng` (name as serif `text-4xl→6xl`; the two ASCII quotes + `v1ncent19` are sky-`text-brand` with a hover underline-glow, outside name parts are `text-ink`), tagline underneath always (`En voyage dans l'espace de Hilbert.`). Handle spelling `v1ncent19` (lowercase v).
- **Two-part masthead** (`components/layout/site-header.tsx`, server-sibling of the header, both in the body flex column):
  1. Identity block — normal flow, scrolls away.
  2. Capsule nav — `position: sticky` pill (`top-3/4`, `rounded-full`), floats pinned for the whole scroll. Chips left (Home first — user-confirmed), `LangSwitch` (中文/EN) + 3-way `ThemeToggle` inside the pill right. Scroll listeners + `requestAnimationFrame` check `getBoundingClientRect().top`; **while actually pinned** it turns frosted white glass (`bg-white/80 backdrop-blur-xl`, dark `#101b2b/80`), otherwise `bg-canvas/90 backdrop-blur-md`.
- **Theme toggle** — ONE cycling button system→light→dark→system (`components/theme/theme-toggle.tsx` + `theme-script.tsx` `beforeInteractive` in `app/layout.tsx`); three lucide icons always in DOM, `globals.css` shows one per `data-theme`. No FOUC.
- **§ headings** — every page-top heading and every homepage module title is `§` (serif italic, `font-serif text-xl italic font-normal text-brand`, `aria-hidden`) + plain black title, with the grey explanatory line/caption underneath unchanged. No eyebrows (`page-header.tsx` auto-adds §; blog/gallery/CV headers same pattern).
- **Content columns** — card/list pages (Home modules, Blog, Gallery, Project list, CV) use `mx-auto max-w-5xl`; prose reading pages (About, single project-note detail) keep the narrower `~max-w-3xl`. `.shell` (nav/footer outer) is 72rem. `html` has `scroll-padding-top: 5.5rem` so anchors clear the pinned pill.
- **Homepage hero** is **not** in a card; intro text sits on the canvas, portrait `figure` floats right, action row below separated by a `border-t` with `clear: both`.
- **Homepage action buttons** — Download CV, GitHub Profile, Contact Email are default-white outline buttons; trailing **More about me** is cyan-filled (`bg-brand text-on-brand`, hover `bg-brand-strong`, arrow on it). Contact Email is `components/home/email-copy-button.tsx`: idle "Contact Email", hover "copy to clipboard", click copies then **"√ email clipped"** for ~1.8 s.
- **Category tones** (chips/accents) — `knowledge` = brand, `cuisine` = tertiary, `documentation` = accent (see `components/blog/blog-index-view.tsx` `TONES`).
- **Content truth** — only real facts about the user. Old Jekyll pages are source material, not instructions; Stitch exports are visual reference only (never copy Stitch's fictional academic copy). Public identity is `v1ncent19`; detailed personal info lives in About/CV only.

## 4. Architecture / file map (new app)

```
app/            route pages (en default; zh nested folders), globals.css, prose.css, layout.tsx
components/
  layout/       site-header (identity+capsule), site-footer, back-to-top, lang-switch, page-header(§)
  theme/        theme-toggle, theme-script
  home/         email-copy-button
  blog/ gallery/ cv/ project/ content(prose.tsx)
content/        profile.json (identity + legacyStats baselines), navigation.ts, about/{en,zh}.md,
                project/*.md (gray-matter front-matter), cv/entries.ts, gallery/items.json (manifest)
lib/            site.ts (identity consts), i18n.ts (en/zh UI copy, `copy`), content.ts (server-only
                loaders: profile/project/gallery + strict validation), legacy.ts (reads _texts/*.md)
scripts/        gallery.mjs (`npm run gallery:gen` — the image pipeline below)
public/assets/  profile avatar, cv PDF, gallery/{thumb,large}/*.webp (96 generated), photos (empty),
                project (mirrored old assets for Next)
```

- **Server-only rule:** loaders touch `node:fs` → import only from server components/pages, never client components. `gallery-view.tsx` is a client component but only `import type { GalleryItem }` from `lib/content.ts`; the pages pass the serialised `items` down.
- **Gallery image pipeline (2026-09-04):** `npm run gallery:gen` runs `scripts/gallery.mjs` — reads full-res originals from **`GalleryPhoto/`** (git-ignored, ~142 MB, never on GitHub), auto-rotates via EXIF and writes `public/assets/gallery/{thumb,large}/<id>.webp` (~480/~1680 long edge, q78, real `DateTimeOriginal` → `YYYY-MM-DD`), then maintains `content/gallery/items.json`. It **never overwrites the human fields** — the bilingual block `place_en/_zh`, `placeLocal_en/_zh`, `title_en/_zh`, `alt_en/_zh`, plus shared `country_code`, `originalUrl`, `color`, `badge` (preserved by `source` filename); the pre-bilingual single-language keys are migrated to `*_en` and blanked on first run. Delete a manifest row to drop a photo. **EXIF GPS is extracted every run** (exifr hands coords back at the TOP level — `parsed.latitude/.longitude`, not `parsed.gps.*`) into `lat`/`lon` as decimal degrees (all 48 originals have GPS); a hand-edited value survives only when the file has no GPS tag. `lib/content.ts` `getGalleryItems()` validates the manifest at build (latitude/longitude optional, any finite number). Uses plain `<img>` (static export, `images.unoptimized`).
- **Copy:** chrome/UI text lives in `lib/i18n.ts` keyed `copy[lang]`. Some keys are now unused after the §/title migration (`blog.eyebrow`, several `home.*`) — harmless; a cleanup pass can remove them.
- **Old Jekyll source still present** at repo root (`index.html`, `About_en.md`, `CV.md`, `_texts/`, `_includes/`, `assets/`, `_config.yml`…). `lib/legacy.ts` reads blog posts straight from `_texts/*.md` at build time. Remove/replace at launch with redirect pages.

## 8. Known gotchas for future agents

- **Next 16 is different** — read `node_modules/next/dist/docs/` before coding (AGENTS.md). `beforeInteractive` in App Router must live in the root layout (eslint flags it — that warning is a false positive).
- `react/no-unescaped-entities`: literal `"` in JSX text must be `&quot;` (used in the header name and footer).
- `lucide-react` v1.40 removed brand icons — `Github` doesn't exist; use `GitBranch`.
- Interactive state must be set only inside event handlers / `requestAnimationFrame` (the `react-hooks/set-state-in-effect` rule) — pattern in `site-header.tsx` (stuck nav) and `back-to-top.tsx`.
- Tailwind v4: any class used by a client component must appear as a full literal somewhere Tailwind scans (full-literal class strings only; see `TONES`/`blog-index-view.tsx`).
- **giscus is client-side and dormant until deploy**: `components/blog/giscus-comments.tsx` renders nothing until hydration reads `<html data-theme>` (rAF idiom), and giscus itself refuses localhost origins — the thread only becomes live on the deployed domain. Instance config (repo/repoId/category/categoryId) was carried over verbatim from the old homepage `index.html`. `key={theme}` remounts the `@giscus/react` iframe on theme change.
- `history.replaceState` (not push) keeps the category deep-link shareable without spamming history — see `selectCategory` in `blog-index-view.tsx`.
- Gallery tile caption uses a CSS **grid-rows 0fr↔1fr** auto-height expansion (rest bar collapses, white card grows) — requires BOTH grid rows' classes as full literals and `min-h-0 overflow-hidden` children; height animates even though content varies. Per-item accent is set as inline CSS vars `--tile-accent`/`--tile-soft` (from `item.color`, `""` → `var(--brand)`; soft = `color-mix(in srgb, <accent> 13%, transparent)`) — Tailwind arbitrary `var()` utilities reference them, so dot/badge/title share one colour per photo.
- exifr returns GPS coordinates at the **top level** (`parsed.latitude`/`parsed.longitude`), not under `parsed.gps.*` — the gallery pipeline reads both defensively. All 48 originals carry GPS (lat always ≥0 → °N; ~20 frames are west-negative → °W, real non-Taiwan travel).
- `StampBadge`/`MetaTime`/`GalleryTile` and the helpers `localized`/`locText`/`bigTitle`/`coordsLine` in `gallery-view.tsx` are plain functions returning JSX or strings (no hooks) — deliberately not component-exported (react-refresh rule applies only to exports). Bilingual reads go through `localized(item, "place"|"placeLocal"|"title"|"alt", lang)` which reads the `${field}_${lang}` key then falls back to the other language via a `Record<string,string>` cast (fields are optional strings — no key may be assumed present).
- Don't reintroduce homepage search, homepage comment threads, a mobile bottom nav, or `Notes` as a top-level route without asking.
